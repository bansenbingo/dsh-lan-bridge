# 0.2.1 更新说明

这是 macOS 兼容性补丁。0.2.0 在某些 Mac 版 DSH 上启动时可能报 JavaScript 错误：

- 客户端不再把 `uiWorkspace` / `sessions` 写进 `inject`，改为运行时 `ctx.get(...)` 可选访问。缺少这些服务时，面板和宿主照常启动，“在 DSH 中打开”会降级为“已写入本机，请从侧栏打开”。
- 宿主不再把 `tools` 写进 `inject`，改为 `ctx.get('tools')` 可选访问。旧版 DSH 没有 tools 服务时只是不注册 AI 工具。
- 安装脚本、zip、README 版本号已更新到 0.2.1。

如果 0.2.0 已经导致 DSH 无法启动：
1. 把 `~/.dsh/plugins/dsh-lan-bridge` 临时改名为 `dsh-lan-bridge.disabled`；
2. 用 `ls -t ~/.dsh/profiles/desktop/package.json.bak.* | head -1` 找到安装脚本备份的 profile，复制回 `package.json`；
3. 重启 DSH，再安装 0.2.1。

下面的 0.2.0 功能说明仍然适用。

# 0.2.0 更新说明

0.2 是一次架构级重写：从“两台机器的 hub/peer”变成“每台机器都是节点的局域网 mesh”，面板也改成设备中心。

## 最重要的变化

1. **去中心化**：不再分主机/成员。每台电脑都运行 HTTP、UDP 发现和同步循环；任意两台已信任设备直接互连。
2. **邀请码 + 信任**：设置里生成邀请码，另一台粘贴加入；发现到的设备默认“待确认”，必须手动信任后才会同步、读文件或借模型。
3. **AirDrop 式传文件**：选择共享工作区里的文件 → 选目标设备 → 收件箱或对方工作区；分块传输、逐块 SHA-256、整文件 SHA-256、断点续传。
4. **远端对话原生打开**：对话页可以看另一台电脑的会话，点“在 DSH 中打开”会 fork 成本机真实 session，并切回 DSH 原生对话界面。
5. **多机多模型**：AI 页可以借用已信任设备的模型；也可以把同一个问题并行发给多台设备。
6. **原生 UI**：面板注册在 DSH 的 sidebar/main slot，颜色和圆角使用 `--dsw-*` 主题变量，自动跟随明暗主题。

## 兼容性

- 旧版 `config.json` 会自动迁移：`machineId` → `nodeId`，旧 `token` 拉伸成 v2 `networkKey`。两台旧机器升级后仍在同一空间。
- 旧版共享区 `store/index.json` 和会话/记忆/清单文件会自动导入；旧索引保留为 `index.v1.json`。
- 旧版的 hubHost/hubPort 会变成 bootstrap 地址；升级后仍需在新面板里“信任”对方一次。

## 装完必须做

**完全退出 DSH 再重新打开**，不是刷新页面。宿主半在启动时加载。重开后在侧边栏点「局域网」：

1. 概览 → 邀请设备（A）→ 另一台设置 → 加入已有空间（B）。
2. 两边互相点“信任”。
3. 点“同步”。

## 安全

- 请求用共享空间密钥做 HMAC-SHA256，5 分钟时间窗 + nonce 去重。
- 待确认设备只能调用 hello，不能同步/读文件/借模型。
- 文件路径限制在共享 root 内，拒绝 `..`、绝对路径、盘符、NUL、符号链接逃逸和常见凭据文件名。
- 远端模型只跑普通 chat completion，不执行工具、不读目标机文件；默认关闭。
- 协议是局域网 HTTP + HMAC，不是端到端加密；不要把 47820 暴露到公网。

## 测试

`npm test` 会跑：v1→v2 迁移、HMAC 重放、传输分块、AI/工具、客户端 slot 注册、宿主 boot、fork 22 项，以及两个真实节点进程的邀请/信任/同步/远端读/下载/发送/借模型/fan-out/fork。
